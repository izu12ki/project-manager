---
title: Backlog からの移行
description: Backlog のユーザー一覧と課題一覧の CSV を取り込む
---

Backlog からエクスポートしたユーザー一覧の CSV を読み込み、まとめて招待できます。招待した人は、Backlog で参加していたプロジェクトと同じキーのプロジェクトに参加します。

課題一覧の CSV からは、課題とコメントをプロジェクトに取り込めます（[課題を取り込む](#課題を取り込む)）。ユーザーを先に取り込み、招待した人が承諾してから課題を取り込んでください。

## プロジェクトを作る

取り込む前に、Backlog と同じキーでプロジェクトを作っておきます。キーは英字で始まる 2〜25 文字で、英大文字・数字・アンダースコア（`_`）が使えます。小文字で入力しても大文字になります。

CSV にあってもまだ作っていないキーは、確認画面に「まだ存在しないプロジェクトがあります」として一覧で出ます。そのまま取り込むと、そのプロジェクトには参加させません。アーカイブ済みのプロジェクトにも参加させません。

## ユーザー一覧の CSV を読み込む

Backlog のスペース設定から、ユーザー一覧の CSV をエクスポートします。Shift_JIS のまま読み込めるので、文字コードを変える必要はありません。使う列は「ハンドルネーム」「メールアドレス」「権限」「状態」「参加中のプロジェクトキー（アーカイブ済みを除く）」です。

管理者で「ユーザー」画面（`/admin/users`）を開き、「Backlog の CSV から招待」の「ユーザー CSV」でファイルを選びます。確認画面に、1 人ずつロール・参加させるプロジェクト・扱い（招待・参加を追加・取り込まない理由）が出ます。見出しのチェックで、取り込める人をまとめて選んだり外したりできます。内容を確かめて「取り込む」を押すと、招待した人に招待メールが届きます。

メール送信を設定していない場合（[メール送信の設定](/guides/mail/)）は、招待メールは送られません。「招待中」の一覧の「リンクを再発行」で 1 人ずつリンクを発行し、本人に渡してください。

取り込む人は 8 人ずつ分けて送ります。Workers の無料プランでは、1 回のリクエストで DB に問い合わせる回数と、メールを送る回数がそれぞれ 50 回までのためです。招待メールは間隔を空けて送るので、8 人で数秒かかります。

メール送信サービスの上限にも注意してください。無料枠などには 1 日に送れる通数の上限があります（[メール送信の設定](/guides/mail/)）。人数が多いときは、日を分けて取り込んでください。招待メールを送れなかった人がいると、取り込んだ後の結果にその人の名前とメールアドレスが出ます。その人にも「リンクを再発行」でリンクを渡してください。取り込みの途中で招待を作れなかった人（確認画面の後に登録した人など）も結果に出ます。CSV を読み込み直すと、その人の今の扱いがわかります。

## ロールの対応

| Backlog の権限 | このツールのロール |
|---|---|
| 管理者 | 管理者 |
| 一般ユーザー、レポーター | メンバー |
| それ以外（ゲストレポーター、ゲストビューワーなど） | ゲスト |

招待する人のロールは、確認画面で 1 人ずつ管理者・メンバー・ゲストから選べます。管理者のロールなら、参加させるプロジェクトがなくても招待します（管理者は全プロジェクトを見られます。[権限](/reference/permissions/)）。

閲覧者には対応付けず、確認画面でも選べません。Backlog のゲストビューワーもゲストになるので、課題の起票やコメントができます。閲覧者にしたい人は、確認画面でチェックを外して取り込みから除き、ユーザー管理の画面かプロジェクト設定の「ゲスト・閲覧者」から閲覧者として招待してください。

## 既にいるユーザー

メールアドレスが同じユーザー（大文字・小文字は区別しません）には招待を送らず、まだ参加していないプロジェクトへの参加だけを追加します。ロールは変えません。期限切れの招待しかない人には、新しく招待を送ります。

## 取り込まれない人

次の人は取り込みません。確認画面の「扱い」に理由が出ます。

- Backlog の状態が「有効」でない
- メールアドレスの形式が正しくない
- CSV 内でメールアドレスが重複している（2 人目以降）
- 招待中（まだ承諾しておらず、期限内）
- このツールで無効になっている
- 参加させるプロジェクトにすべて参加済み（このツールの管理者を含む）
- 参加できるプロジェクトがない（管理者のロールなら招待します）
- 確認画面でチェックを外した

## 100 人を超えるとき

1 回に取り込めるのは 100 人まで（招待と参加の追加の合計）です。超えるときは、確認画面でチェックを外して 100 人以内にして取り込み、もう一度同じ CSV を読み込んで残りを取り込みます。招待した人は、次の確認画面で「招待中」として除かれます。CSV は 1 ファイル 1,000 人まで読み込めます。

## 招待を受ける人の名前

招待を受ける画面の名前欄には、Backlog のハンドルネームが入っています。本人が登録するときに変えられます。

## 課題を取り込む

### 順番

先にユーザーを取り込み（上の手順）、招待した人が承諾してから課題を取り込みます。課題の登録者・担当者・コメントの投稿者は、名前でこのツールのユーザーに対応付けます。招待を承諾していない人は対応付けられず「不明なユーザー」になり、後から本人に付け替えることはできません。

### 課題 CSV を読み込む

Backlog の課題一覧（課題検索の画面）から CSV をエクスポートします。Shift_JIS のまま読み込めます。

管理者で、取り込み先のプロジェクトの設定画面を開き、「Backlog の CSV から課題を取り込む」の「課題 CSV」でファイルを選びます。まだ何も書き込まれず、確認画面が出ます。

- 取り込む課題とコメントの件数、振られる番号
- 新しく作るステータス・種別・カテゴリー・マイルストーン
- 取り込まない行とその理由（件名がない、日付の形式が正しくない、など）
- 人の対応付け（Backlog の名前 → このツールのユーザー）

名前は、前後と途中の空白（全角・半角）を無視して比べ、一致するユーザーを自動で選びます。同じ名前のユーザーが複数いるときは選びません。対応先は 1 人ずつ選び直せます。プロジェクトに参加していない人を選ぶと、取り込むときにプロジェクトに参加させます。

内容を確かめて「取り込む」を押すと、全件をまとめて書き込みます。途中で失敗したときは何も書き込みません。取り込みでは通知（アプリ内・Slack・メール）を送らず、編集履歴も残しません。

Workers の無料プランでは、取り込みの処理が 1 リクエストの CPU 時間の上限（10ms）を超えます。たまに超える分は許されるので、1 回で取り込める 500 件まで取り込めることを確かめています（2026-11）。「Worker exceeded resource limits」（エラー 1102）で失敗したときは、課題一覧で取り込めたかを確かめ、取り込めていなければ CSV を分けて取り込み直してください。

### 項目の対応

| Backlog | このツール |
|---|---|
| 件名 | タイトル。200 文字を超えるときは 200 文字に切り詰める（元の件名は本文の末尾に残す） |
| 詳細 | 本文 |
| 種別 | 同じ名前の課題種別（なければ作る） |
| カテゴリー（複数） | 同じ名前のカテゴリーをすべて（なければ作る） |
| マイルストーン | 同じ名前のマイルストーン（なければ作る）。複数あるときは 1 つ目を使う |
| 状態 | 同じ名前のステータス。なければ、未対応 → 未着手、処理中 → 進行中、処理済み → レビュー、完了 → 完了。それ以外は同じ名前のステータスを作る |
| 優先度 | 高・中・低 → 高・中・低 |
| 完了理由 | 同じ名前の完了理由 |
| 担当者 | 対応付けたユーザー |
| 登録者・コメントの投稿者 | 対応付けたユーザー。いなければ「不明なユーザー」 |
| 登録日・更新日 | 作成日時・更新日時 |
| 開始日・期限日 | 開始日・期限日 |
| 親課題キー | 親課題（下記） |
| コメント | 古い順に登録し、日時は Backlog のコメントの日時 |

本文の末尾には、区切り線の後に移行情報を残します。元のキー（`Backlog から移行: PROJ-12`）のほか、切り詰めた件名の元の全文、対応付けられなかった担当者の名前、2 つ目以降のマイルストーン、発生バージョン、予定時間、実績時間、添付ファイルの件数などです。登録者やコメントの投稿者を対応付けられなかったときは、本文の先頭に元の名前（`（Backlog: 山田 太郎）`）を残します。添付ファイルそのものは CSV に含まれないので移せません。

「不明なユーザー」はログインできない専用のユーザーで、ユーザー一覧・担当者やメンションの候補・通知の対象には出ません。

### 番号と親課題

番号はプロジェクトの続きから、Backlog の課題番号の小さい順に振ります。本文やコメント中の `PROJ-12` のような文字は書き換えません。

親課題が同じ CSV にあるか、前に取り込んだ課題なら、その課題を親にします。このツールの子課題は 1 階層までなので、親にする課題がほかの課題の子課題になるときは親を設定せず、本文の末尾に元の親課題キーを残します。

### 大きなプロジェクト

1 回に取り込めるのは、課題 500 件・コメント 5,000 件・CSV 10MB までです。超えるときは、Backlog で課題番号の範囲などで絞り込んで CSV を分け、番号の小さい範囲から順に取り込んでください。分けて取り込んでも、前に取り込んだ課題を親にできます。同じ課題（同じキー）は二重に取り込めません。

### 日時

CSV の日時にはタイムゾーンが書かれていないので、取り込む人のブラウザのタイムゾーンで読みます。

Backlog は株式会社ヌーラボの登録商標です。
