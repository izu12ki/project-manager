招待メールとパスワードリセットのメールは、次のどれかで送ります。

| | 使える条件 | 料金（2026-10 時点） |
|---|---|---|
| **Cloudflare Email Sending（Paid プランなら推奨）** | Workers Paid プランで、送信元ドメインの DNS を Cloudflare で管理している | Workers Paid プランに月 3,000 通まで含まれる。超えた分は 1,000 通あたり 0.35 ドル |
| SMTP2GO | DNS の管理先は問わない | 無料枠: 月 1,000 通・1 日 200 通 |
| Resend | DNS の管理先は問わない | 無料枠: 月 3,000 通・1 日 100 通（宛先 1 件ごとに 1 通と数える） |

Workers Paid プランを使っていて、送信元ドメインの DNS を Cloudflare で管理しているなら **Cloudflare Email Sending を使ってください**。別のサービスの契約も API キーも要りません。Workers の無料プランの場合と、DNS を Cloudflare 以外で管理している場合は、SMTP2GO か Resend を使います。

最新の条件は各サービスの料金ページで確認してください。

## Cloudflare Email Sending（推奨）

:::caution[ベータ版]
2026-10 時点ではベータ版です。新しいアカウントは 1 日に送れる通数が少なめに設定されていて、送信の実績に応じて自動で引き上げられます。
:::

<Steps>

1. 送信元に使うドメインを Cloudflare に追加していなければ、追加して DNS を Cloudflare に移す
2. ダッシュボードの「Compute → Email Service → Email Sending」で「Onboard Domain」を選び、ドメインを選ぶ（`pnpm exec wrangler email sending enable example.com` でもよい）。SPF・DKIM・DMARC のレコードは自動で追加される
3. シークレットを登録して再デプロイする

   ```bash
   cd apps/web
   pnpm exec wrangler secret put MAIL_FROM       # 例: Project Manager <noreply@example.com>（手順 2 のドメインのアドレス）
   pnpm exec wrangler secret put MAIL_PROVIDER   # cloudflare（必ず最後に登録する）
   pnpm deploy
   ```

</Steps>

`MAIL_API_KEY` は要りません。送信には Worker のバインディング（`apps/web/wrangler.jsonc` の `send_email`）を使います。

:::caution[DMARC レコードが無いドメインの場合]
手順 2 で `p=reject` のレコードが追加されます。そのドメインで Google Workspace などほかのサービスからもメールを送っている場合は、そちらも SPF・DKIM を設定済みか確認してください。
:::

## SMTP2GO / Resend

<Steps>

1. サービスに登録し、送信元に使うドメインを認証する（DNS に SPF / DKIM レコードを追加）。SMTP2GO では、DNS を変えられない場合に送信元のアドレスだけを確認する方法（Single sender emails）も使えるが、SPF・DKIM が揃わないため迷惑メールに入りやすい
2. API キーを発行する
3. シークレットを登録して再デプロイする

   ```bash
   cd apps/web
   pnpm exec wrangler secret put MAIL_API_KEY
   pnpm exec wrangler secret put MAIL_FROM       # 例: Project Manager <noreply@example.com>
   pnpm exec wrangler secret put MAIL_PROVIDER   # smtp2go または resend（必ず最後に登録する）
   pnpm deploy
   ```

</Steps>

:::caution[MAIL_PROVIDER は最後に登録する]
シークレットは登録した時点で本番に反映されます。`MAIL_FROM`（SMTP2GO・Resend では `MAIL_API_KEY` も）が無いまま `MAIL_PROVIDER` を変えると、そのあいだ全てのページがエラーになります。
:::

## メール送信を設定しない場合

`MAIL_PROVIDER=console`（既定）のままでは、招待メールとパスワードリセットのメールは実際には送信されず、Workers のログに出力されるだけです（`apps/web` で `pnpm exec wrangler tail`）。招待は画面に表示されるリンクを直接渡せますが、パスワードリセットのリンクはログから取り出す必要があります。

## メールが届かないとき

- 送信に失敗してもアプリの操作自体は成功します。失敗は Workers のログ（ダッシュボードの Observability、または `pnpm exec wrangler tail`）に `invitation mail failed`（パスワードリセットは `reset password mail failed`）として出ます。
- Cloudflare Email Sending では、ダッシュボードの「Email Sending」のログでも送信結果を確認できます。
- `example.com` などの予約ドメイン（RFC 2606・6761）宛てのメールは送りません。ログに `[mail] skipped` と出ます。デモやテスト用の架空のユーザーに送って、バウンスで送信元の評価を下げないためです。
- 招待は管理画面の「未使用の招待」から「リンクをコピー」でいつでも渡せます。

:::caution
「リンクをコピー」を押すと招待を再発行し、以前のリンクは無効になります。
:::
