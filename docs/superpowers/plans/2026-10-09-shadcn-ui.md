# shadcn-svelte UI Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 既存の全画面を shadcn-svelte / shadcn-svelte-extras の部品に置き換え、サイドバー型レイアウトとダークモードを導入する（機能・権限・データの流れは変えない）。

**Architecture:** shadcn-svelte の CLI で `src/lib/components/ui/` に部品のソースを生成し、各ページの自作 Tailwind クラス（`.input` / `.btn` / `.btn-primary` / `.card`）を部品に置き換える。確認ダイアログは共通部品 `ConfirmAction.svelte` に集約する。フォームは既存の form actions + `use:enhance` のまま。

**Tech Stack:** shadcn-svelte CLI 1.7.0 / bits-ui 2.19 / mode-watcher 1.1 / svelte-sonner 1.2 / tailwind-variants 3.3 / shadcn-svelte-extras（copy-button, password, light-switch）/ 既存: SvelteKit 3, Svelte 5.57, Tailwind v4, @lucide/svelte

**Spec:** `docs/superpowers/specs/2026-10-09-shadcn-ui-design.md`

**検証済みの事実:** スクラッチ環境で init / add / extras / check / lint / build / Playwright を実行して確認した結果が下の「Verified Facts」節にある。コードを書く前に必ず読むこと。

**このプランの書き方について:** 移行対象のページは既に存在し、ロジック（load / actions / 権限フラグ / dnd）は変えない。そのため各ページのタスクは「現在のファイルを読み、下の Patterns 節の書き方でマークアップだけを置き換える」形で書いている。新規に作る共通部品とレイアウトは完全なコードを示す。

## Global Constraints

- E2E が依存する文言を変えない: ボタン「新規プロジェクト」「作成」「招待する」「ゲストを招待」「新規課題」「起票する」「保存」「コメントする」「ログイン」「ログアウト」「登録する」「セットアップを完了」、ラベル「キー」「プロジェクト名」「メールアドレス」「パスワード」「名前」「ロール」「参加プロジェクト」「ゲストのメールアドレス」「招待リンク」「タイトル」「担当者」「ステータス」「コメントを追加」、見出し「プロジェクト」、`data-testid="column-<status>"` / `card-<number>`、保存後に「保存しました」が画面に出ること。
- `Field.Label` は入力と自動で紐づかない。**必ず `for` と `id` を対で付ける**（`getByLabel` のため）。
- shadcn の `Button` の既定は `type="button"`。**フォーム送信ボタンには `type="submit"`** を付ける。
- 選択入力は `NativeSelect`（ネイティブ `<select>`）。shadcn の `Select` は使わない。
- 招待リンク再発行ボタンのすぐ横に「コピーすると招待を再発行し、以前のリンクは無効になります」を常時表示する。
- 権限フラグ（`perms` / `can()` / `isAdmin`）による出し分けとサーバー側ロジックは変えない。JavaScript なしでもフォームが送信できること（確認ダイアログの操作は `<noscript>` の送信ボタンで代替）。
- 色は shadcn の配色トークン（`bg-background`, `text-muted-foreground`, `border` など）だけを使う。`bg-blue-600` のような生の色や手書きの `dark:` は使わない。`space-y-*` ではなく `flex flex-col gap-*`。
- `{@html}` は `renderMarkdown` の出力だけ。
- 各タスクの最後に apps/web で `pnpm test:unit --run && pnpm check && pnpm lint && pnpm test:e2e` が通ること。
- 全タスク完了・検証後は、確認なしで本番にデプロイしてよい（`CLOUDFLARE_ACCOUNT_ID` は環境変数で渡し、コミットしない）。

## Review Focus

1. **同じリンク名が 2 か所に出る** — サイドバーとトップのカードの両方にプロジェクト名リンクが出るため、E2E の `getByRole('link', { name: /ACME サイト改修/ })` が strict mode 違反になる（Task 2 で E2E を `main` にスコープする）。
2. **確認ダイアログを閉じ忘れる** — `AlertDialog.Action` はダイアログを閉じない。送信後も開いたままにならないこと（Task 3 の `ConfirmAction` で `open = false`）。
3. **ダークモードで読めない文字** — 生の色クラスが残っていると、ダークで背景と同化する（Task 9 で `grep` とスクリーンショットで確認）。
4. **「保存しました」が 2 か所に出る** — インライン表示とトーストを両方出すと、E2E の `getByText` が 2 件にマッチして失敗する（トーストに一本化）。
5. **Worker サイズの肥大化** — extras の Password が zxcvbn の辞書を同梱し、+1.7MB になる（Task 1 で削除する）。

- **add**（`-o` が必須。ないと上書き確認で止まる）:
  ```bash
  pnpm dlx shadcn-svelte@latest add -y -o button input textarea label field native-select card table badge alert alert-dialog sonner empty sidebar collapsible separator dropdown-menu avatar tooltip skeleton
  pnpm dlx shadcn-svelte@latest add -y -o https://shadcn-svelte-extras.com/r/copy-button.json https://shadcn-svelte-extras.com/r/password.json https://shadcn-svelte-extras.com/r/light-switch.json
  ```
  extras の追加で `src/lib/utils.ts` が `cn = twMerge(clsx(...))` 版に上書きされる（init が入れた `cn` npm パッケージは不要になる）。`src/lib/components/button.svelte`（extras のボタンラッパー）と `src/lib/hooks/use-clipboard.svelte.ts` も追加される。
- **入る依存**: bits-ui ^2.19.5, mode-watcher ^1.1.0, svelte-sonner ^1.2.1, @internationalized/date ^3.12.4, tailwind-variants ^3.3.1, tw-animate-css ^1.4.0, @fontsource-variable/inter ^5.3.0, clsx ^2.1.1, tailwind-merge ^3.7.0, runed ^0.37.1, svelte-toolbelt ^0.10.6, @zxcvbn-ts/*（Task 1 で削除）。release-age の除外設定は不要だった。
- **生成ファイルの修正が必要なもの**:
  - `native-select.svelte` は TS 6 で svelte-check エラーになる。props の型 `Omit<WithElementRef<HTMLSelectAttributes>, 'size'>` を `Omit<HTMLSelectAttributes, 'size'> & { ref?: HTMLSelectElement | null }` に替え、`WithElementRef` の import を消す。
  - extras の Password は zxcvbn を動的 import し、Worker に辞書が同梱されて +1.7MB になる。`password.svelte.ts` の `loadZxcvbnRunner` を `const loadZxcvbnRunner = async (): Promise<ZxcvbnRunner> => { throw new Error('zxcvbn removed'); };` に置き換え、`password-strength.svelte` を削除し、`password/index.ts` から `Strength` を外し、`@zxcvbn-ts/core` `@zxcvbn-ts/language-common` `@zxcvbn-ts/language-en` を remove する（削除後 3683 KiB / gzip 701 KiB を確認済み）。
  - 生成された shadcn の部品は prettier 未整形で、`pnpm lint` が約 150 ファイル失敗する。→ `apps/web/.prettierignore` に `/src/lib/components/ui/` を追加する（生成コードは再生成・`update` されるため整形対象外にする）。
- **使い方の要点**:
  - `import * as Field from '$lib/components/ui/field'` → `Field.Group` / `Field.Field` / `Field.Label` / `Field.Description` / `Field.Error`
  - `import * as NativeSelect from '$lib/components/ui/native-select'` → `NativeSelect.Root`（中身は本物の `<select>`。`class` は外側の div に付く。`id` `name` `disabled` `value` は `<select>` に渡る）/ `NativeSelect.Option`
  - `import { Button, buttonVariants } from '$lib/components/ui/button'`。`href` を渡すと `<a>` になる。variant: default|outline|secondary|ghost|destructive|link、size: default|xs|sm|lg|icon|icon-xs|icon-sm|icon-lg
  - `Badge` の variant: default|secondary|destructive|outline|ghost|link。`Alert.Root` の variant: default|destructive
  - `AlertDialog.Action` はダイアログを閉じない。Content は body にポータルされるので form の中に置けない → `form="<id>"` 属性で外のフォームを送信し、`bind:open` を自分で false にする
  - `Sidebar.MenuButton` に `href` はない → `{#snippet child({ props })}<a href=... {...props}>...</a>{/snippet}`。`Sidebar.Inset` が `<main>` を描画する
  - `<ModeWatcher />` と `<Toaster />` はルートレイアウトに 1 回だけ置く（Toaster は mode-watcher の状態を読む）。`toast` は `svelte-sonner` から import
  - extras: `CopyButton`（`text` 必須、アイコンのみ）、`Password.Root` > `Password.Input`（`id` `name` `autocomplete` `required` が渡る）+ `Password.ToggleVisibility`、`LightSwitch`（`variant` `size`）
- **Inter フォント**: UI は日本語なので Inter は効かない。layout.css の `@import "@fontsource-variable/inter";` と `html { font-sans }` の Inter 指定を外し、パッケージを remove してよい（Task 1）。

## Patterns（各ページで使う書き方）

**入力欄（ラベルと必ず for/id で紐づける）**
```svelte
<Field.Field>
	<Field.Label for="issue-title">タイトル</Field.Label>
	<Input id="issue-title" name="title" required maxlength={200} value={issue.title} />
</Field.Field>
```
複数の入力は `<Field.Group>` で囲む（`div` + `space-y-*` は使わない）。

**選択**
```svelte
<Field.Field>
	<Field.Label for="assignee">担当者</Field.Label>
	<NativeSelect.Root id="assignee" name="assigneeId" disabled={!perms.assign}>
		<NativeSelect.Option value="">未割り当て</NativeSelect.Option>
		{#each assignees as u (u.id)}
			<NativeSelect.Option value={u.id} selected={u.id === issue.assigneeId}>{u.name}</NativeSelect.Option>
		{/each}
	</NativeSelect.Root>
</Field.Field>
```

**送信ボタン**: `<Button type="submit">保存</Button>`。アイコン付きは `<Button type="submit"><Plus data-icon="inline-start" />新規課題</Button>`（アイコンにサイズクラスを付けない）。リンクのボタンは `<Button href="/projects/{key}/issues/new">`。

**フォームのエラー**
```svelte
{#if form?.message}
	<Alert.Root variant="destructive">
		<Alert.Description>{form.message}</Alert.Description>
	</Alert.Root>
{/if}
```

**成功通知（インライン表示はやめてトーストに一本化）**
```svelte
<script lang="ts">
	import { toast } from 'svelte-sonner';
	$effect(() => {
		if (form?.saved) toast.success('保存しました');
	});
</script>
```

**確認が必要な操作**: Task 3 で作る `ConfirmAction` を使う。
```svelte
<ConfirmAction
	action="?/disable"
	fields={{ id: u.id }}
	title={`${u.name} を無効化しますか？`}
	description="すぐにログアウトされます。"
	confirmLabel="無効化する"
>
	{#snippet trigger()}無効化{/snippet}
</ConfirmAction>
```

**表**: `Table.Root` > `Table.Header` > `Table.Row` > `Table.Head` / `Table.Body` > `Table.Row` > `Table.Cell`。

**空表示**
```svelte
<Empty.Root>
	<Empty.Header>
		<Empty.Title>課題はありません</Empty.Title>
	</Empty.Header>
</Empty.Root>
```

**カード**: `Card.Root` > `Card.Header`（`Card.Title` / `Card.Description`）> `Card.Content` > `Card.Footer`。

**ステータス・優先度などの表示**: `<Badge variant="secondary">{STATUS_LABEL[i.status]}</Badge>`。優先度 `urgent` / `high` は `variant="destructive"` / `"default"`、それ以外は `"outline"`。

- [ ] **Step 1: レイアウトの load でサイドバー用のプロジェクトを返す**

`apps/web/src/routes/+layout.server.ts`:
```ts
import { appContext } from '$lib/server/context';
import { listProjects } from '$lib/server/services/projects';
import type { LayoutServerLoad } from './$types';

export const load: LayoutServerLoad = async ({ locals }) => {
	if (!locals.user) return { user: null, projects: [] };
	const projects = await listProjects(appContext(locals));
	return {
		user: locals.user,
		projects: projects.map((p) => ({ key: p.key, name: p.name, archived: !!p.archivedAt }))
	};
};
```
