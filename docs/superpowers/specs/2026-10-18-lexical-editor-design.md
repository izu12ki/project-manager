# Markdown の見たまま編集（Lexical）設計書

日付: 2026-10-18
前提: `2026-10-09-project-manager-design.md`（本体設計書）、`2026-10-13-attachments-design.md`（添付）、`2026-10-14-notifications-design.md`（メンション）。

## 1. 目的

課題の本文とコメントは Markdown で書けるが、入力欄は素の textarea で、次の 2 点に困っている。

- プレビューがなく、保存するまで仕上がりが分からない。
- 書きづらい。特に箇条書きのネスト。

入力欄を見たまま編集（WYSIWYG）のエディタに置き換え、入力中に完成形の見た目が分かり、Tab / Shift+Tab で箇条書きを深く・浅くできるようにする。

### ゴール

- 本文・コメントの 4 か所の入力欄を同じエディタにそろえる（§3）。
- 編集中の見た目を、保存後の表示（`.markdown`）にそろえる。
- Markdown を知っている人は、これまでどおり `- ` `**` などを打てば書式になる。
- 「Markdown で編集」の切り替えで、ソースを直接見て直せる。
- メンション（`@`）と添付（貼り付け・ドロップ・添付ボタン）は、今と同じ操作で使える。
- 表示側（サーバの Markdown→HTML）を、エディタと同じ解析処理に移し、エディタと表示のずれをなくす。

### 含まないもの

- 保存形式の変更。DB には今までどおり Markdown 文字列を保存する。
- 見出し・引用などのツールバーボタン（Markdown で打てば書式にはなる。ボタンは §5 のものだけ）。
- 表の見たまま編集（表は崩さず残すだけ。§4.5）。
- 文字色・文字サイズなど、Markdown で表せない書式。
- 共同編集（同時編集のリアルタイム反映）。
- 既存データの一括書き換え（マイグレーション）。

### 失敗とみなすもの（動いていても NG）

- 既存の本文を開いて、何も直さずに保存しただけで、保存される文字列が変わる。
- 1 回の改行で改行していた既存の本文が、新しい表示で 1 行につながる。
- 課題を見るだけのページで、表示が遅くなる（エディタのコードを最初に読み込む）。
- 生の HTML や `javascript:` リンクが表示側で有効になる。
- 日本語入力の変換確定（Enter）で、メンション候補の選択や段落の分割が誤って起きる。

## 2. 方式と主な判断

| 項目 | 決定 | 判断した人 |
|---|---|---|
| エディタ | Lexical 0.52 系（`lexical` と `@lexical/*` はすべて同じ版に固定） | ユーザー |
| UI 部品 | ツールバー・メンション候補・添付はすべて自前の Svelte。ラベルは日本語、アイコンは lucide。svelte-lexical は使わない（lexical 0.40 固定で `@lexical/mdast` と同居できないため） | ユーザー |
| Markdown の読み書き | `@lexical/mdast`（CommonMark と GFM の拡張、入力ショートカットの拡張） | Claude |
| 表示側 | markdown-it から、`mdast-util-from-markdown` と GFM 拡張 → hast → HTML に移す（エディタと同じ解析処理） | ユーザーが方針を承認 |
| ソース切り替え | 残す（表示速度に影響しない作りにする） | ユーザー |

React は使わない。`buildEditorFromExtensions` で組み立て、Svelte の `{@attach}` から DOM に取り付ける。

## 3. 対象の入力欄

| 場所 | 今 | フォーム |
|---|---|---|
| 課題作成の本文 | `MarkdownEditor.svelte`（`routes/projects/[key]/issues/new/+page.svelte`） | `use:enhance` の通常フォーム。`name="description"` |
| 課題詳細の本文編集 | `IssueView.svelte` の textarea | remote form（`save.fields.description`）。`form={attrFormId}` で外のフォームに属する |
| コメントの新規投稿 | 同上 | remote form（`post.fields.body`） |
| コメントの編集 | 同上 | remote form（`edit.fields.body`） |

4 か所とも新しい `MarkdownEditor.svelte` に置き換える。課題詳細の 3 か所で直接使っている `autosize`・`uploadable`・`MentionMenu`・`AttachButton` は、エディタの中に入れる。

## 4. エディタの構造

### 4.1 textarea をフォームの値の持ち主として残す

エディタは今の textarea を消さず、その上に重ねる形で作る。

- textarea はフォームの値（`name`、remote form の `.as(...)` の属性、`required`、`form` 属性）をそのまま持つ。フォーム送信、`form.reset()`、remote form の検証は今までどおり textarea を通して動く。
- 見たまま編集のモードでは、textarea を隠して Lexical の編集領域を見せる。Lexical の内容が変わったら Markdown に変換して textarea の値に入れ、`input` イベントを発火する（`bind:value` と remote form に伝えるため。今の `notify` と同じ考え方）。
- 「Markdown で編集」のモードでは、textarea をそのまま見せる。見たまま編集に戻すときに、textarea の値を Lexical に読み込み直す。
- `form.reset()`（投稿後のコメント欄など）で textarea の値が戻ったら、Lexical にも反映する。

この作りなら、ソース切り替えは textarea の表示・非表示だけで済み、ページの重さは増えない。

### 4.2 読み込みのタイミング

- Lexical と `@lexical/mdast` は動的 import で読み込み、ページの最初の表示に含めない。
- 読み込みが終わるまでは textarea をそのまま見せ、操作もできる（読み込み後に、その時点の値で Lexical を初期化する）。
- 読み込みを始めるタイミングは builder に任せる（例: エディタが画面に出た後のアイドル時、またはフォーカス時）。条件は、課題を見るだけのページの表示が今より遅くならないこと。

### 4.3 何も直さなければ元の文字列を保つ

Markdown→Lexical→Markdown の変換は、書き方の違い（`*` と `-`、空行の数など）を正規化する。何も直していない本文の保存文字列が変わらないように、次を守る。

- 読み込んだ直後の Lexical の内容から書き出した Markdown を基準として覚えておく。
- 書き出した Markdown が基準と同じ間は、textarea の値を元の文字列のまま保つ。
- 実際に編集して内容が変わったときだけ、書き出した Markdown を textarea に入れる。

- 実際に編集した後は、本文全体が正規化された書き方で保存されてよい（`*` が `-` に、`1)` が `1.` になるなど）。条件は、`renderMarkdown` の結果が変わらないこと（Claude の判断）。

### 4.4 改行

- 今の表示は `breaks: true` で、1 回の改行も改行として表示している。既存の本文はこれを前提に書かれているので、新しい表示でも 1 回の改行は `<br>` にする。
- エディタでは Enter で段落を分け（Markdown では空行）、Shift+Enter で段落内の改行（Markdown では 1 回の改行）にする。
- 既存の本文の 1 回の改行は、エディタに読み込んだときも段落内の改行として表示する。`@lexical/mdast` の標準の挙動が違う（空白につなげるなど）場合は、読み込み・書き出しの処理を足して合わせる。

### 4.5 扱うブロック

| 書式 | エディタでの扱い |
|---|---|
| 段落、太字、斜体、打ち消し線、インラインコード、リンク | 見たまま編集できる |
| 箇条書き（ネスト）、チェックリスト | 見たまま編集できる。Tab / Shift+Tab でネスト |
| 番号付きリスト | 見たまま編集できる。開始番号（`3.` から始まるなど）を保つ |
| 見出し、引用、区切り線、コードブロック | 見たまま編集できる（Markdown の入力ショートカットで作る） |
| 表 | 編集できないブロックとして表示し、元の Markdown をそのまま保つ。直すときは「Markdown で編集」を使う（ユーザーの判断） |
| 生の HTML（`<br>` など） | 文字として保つ。表示側でも文字として表示される（今と同じ） |
| メンション、画像 | §6・§8 |

### 4.6 外からの貼り付け

Web ページ・Google ドキュメント・Slack などから書式付きの文章を貼り付けたとき（ユーザーの判断）:

- 段落・太字・斜体・打ち消し線・インラインコード・リンク・見出し・リスト・引用・コードブロックは残す。
- 文字色・フォント・背景色などの装飾は捨てる。
- 外部サイトの画像は取り込まない（捨てる）。画像を本文に入れる手段は、添付のアップロードだけにする。
- 表は §4.5 に合わせて、Markdown の表として取り込めない場合はテキストにする（Claude の判断）。
- ファイルを含む貼り付けは、今までどおり添付のアップロードにする（§8）。

## 5. ツールバー

左から次の順に並べる。ラベル（`title` / `aria-label`）は日本語、アイコンは lucide。

| ボタン | Markdown | 補足 |
|---|---|---|
| 太字 | `**x**` | |
| 打ち消し線 | `~~x~~` | 新規 |
| コード | `` `x` `` / コードブロック | 複数行を選んでいればコードブロック（今の挙動と同じ） |
| リンク | `[x](url)` | URL の入力方法は builder に任せる（小さな入力欄のポップオーバーなど） |
| 箇条書き | `- ` | |
| チェックリスト | `- [ ] ` | |
| 添付 | — | 添付先のプロジェクトがあるときだけ表示する（今の `projectKey` と同じ条件） |
| Markdown で編集 | — | モードの切り替え。押している間はオン表示にする |

- カーソル位置の書式に合わせて、太字・打ち消し線などのボタンをオン表示にする。
- ヒントの文言（「Markdown が使えます・@ でメンション・ファイルは貼り付けかドロップでも添付できます」）は今の `MarkdownEditor` のものを引き継ぐ。課題詳細の本文にある「右／上の『保存』で反映されます」は呼び出し側に残す。
- キーボード操作: Ctrl/Cmd+B（太字）、Tab / Shift+Tab（箇条書きを深く・浅く）、Ctrl/Cmd+Z / Shift+Z（元に戻す・やり直す）。リストの外での Tab は、フォーカス移動のまま（キーボードだけで操作する人がエディタから出られなくならないように）。

## 6. メンション

### 6.1 保存形式

今と同じ `@[表示名](user:<uuid>)`（`$lib/mentions` の `MENTION_SOURCE`）。通知（`extractMentionIds`・`mentionsToPlain`）は変えない。

### 6.2 解析

CommonMark で `@[表示名](user:<uuid>)` を解析すると、「`@` で終わるテキスト」と「URL が `user:<uuid>` のリンク」に分かれる。エディタの読み込みと表示側の両方で、この並びを見つけてメンションに置き換える。この置き換えは mdast の上の関数として共通化し、`$lib` に置く（サーバとブラウザの両方から使う）。

- コード（インライン・ブロック）の中は置き換えない（今と同じ）。
- uuid が `MENTION_SOURCE` に合わないものは、普通のリンクのまま扱う。ただし `user:` は表示側で許可しないプロトコルなので、リンクにはならない（§7）。

### 6.3 エディタ

- メンションは Lexical の独自ノードにする。1 つの塊として扱い、表示は保存後と同じバッジ（`.mention`）。Backspace で丸ごと消える。
- `@` の入力で候補を出す。候補の絞り込み・並び・件数は今の `findMentionQuery` / `filterCandidates` と同じにする。
- ↑↓ で選択、Enter / Tab で確定、Esc で閉じる。変換確定中（`isComposing`）の Enter では確定しない。
- 候補メニューの位置は Lexical の選択範囲の座標から求める（textarea 用の `caret.ts` は使わない）。
- 「Markdown で編集」のモードでは、今の `MentionMenu`（textarea 用）をそのまま使う。

## 7. 表示側（サーバ）

`src/lib/server/markdown.ts` の `renderMarkdown(src: string): string` の入出力はそのままにして、中身を差し替える。

- 解析: `mdast-util-from-markdown` と GFM 拡張（打ち消し線、チェックリスト、表）。エディタの `@lexical/mdast` と同じ解析処理にする。
- URL の自動リンク: GFM の自動リンク（autolink literal）は使わず、今の markdown-it と同じ `linkify-it` でテキストの中の URL を探してリンクにする（ユーザーの判断）。`example.com` のような `http` の付かない URL や、「詳細はhttps://…」のように日本語に直接続く URL も、今と同じようにリンクになること。コードと既存のリンクの中は対象にしない。エディタ側も、自動リンクの読み書きで同じ規則を使う（エディタ上でリンクとして見せるかどうかは builder に任せる。保存される文字列は URL のままにする）。本番データとの突き合わせはしない。
- メンション: §6.2 の共通の置き換えのあと、`<span class="mention">@表示名</span>` にする。
- 改行: 段落内の 1 回の改行を `<br>` にする（§4.4）。
- 生の HTML: 実行も削除もせず、文字としてエスケープして表示する（今の `html: false` と同じ。今のテスト「生の HTML はエスケープする」が通ること）。
- リンク: `http:` `https:` `mailto:` と、相対 URL（`/projects/...` の添付）だけをリンクにする。それ以外（`javascript:` など）はリンクにしない。リンクには `rel="noopener noreferrer nofollow"` と `target="_blank"` を付ける。
- 画像: `<span class="md-img">` で包む（拡大表示用。今と同じ）。画像の URL にも、リンクと同じプロトコルの制限をかける。
- `src/lib/server/markdown.test.ts` の既存テストは、期待値を変えずにすべて通すこと。markdown-it は、置き換えが終わったら依存から外す。

## 8. 添付

- 貼り付け・ドロップ・添付ボタンでのアップロード処理（`uploadFile`、サイズ上限、アップロード中は送信を止める `trackUpload`）は今のものを使う。
- 見たまま編集のモードでは、アップロード中の表示をエディタ上に出し（例: 「アップロード中: ファイル名」の仮の要素）、終わったら画像またはリンクに置き換え、失敗したら消してエラーの通知を出す。今の textarea 版と同じ挙動にする。
- 画像は Lexical の独自ノードで表示する（表示は `.md-img` と同じ見た目）。Markdown では `![名前](url)` として読み書きする。画像以外は普通のリンクになる（今の `markdownFor` と同じ形）。
- アップロード中にモードを切り替えた場合の扱いは builder に任せる。条件は、仮の要素が保存される本文に残らないこと、アップロードの結果が失われないこと。

## 9. 見た目

- 編集領域の見た目は、`layout.css` の `.markdown` のスタイル（段落・リストの余白、コード、メンション、画像）に合わせる。可能なら同じクラスを編集領域に付けて共有する。
- 枠・フォーカス時の表示・ツールバーの見た目は、今の `MarkdownEditor` のものを引き継ぐ。
- 高さは今の `autosize` と同じく、内容に合わせて伸び、上限を超えたらスクロールする。最小の高さは今の `rows`（作成 10・本文 10・コメント 3〜4）に相当する高さにする。
- placeholder（「課題の詳細」など）は、空のときに編集領域に表示する。

## 10. テスト

- 単体（vitest）
  - `renderMarkdown`: 既存テストすべて、および打ち消し線・チェックリスト・ネストした箇条書き・1 回の改行の `<br>`・表・`example.com` と「詳細はhttps://example.com/です」の自動リンク（markdown-it と同じ結果）。
  - 往復: 既存の書き方の本文（ネストした箇条書き、チェックリスト、番号付きリスト、見出し、引用、表、生の HTML、コード、メンション、画像、1 回の改行を含む）を、Markdown→Lexical→Markdown と変換し、`renderMarkdown` の結果が変わらないこと。
  - §4.3: 読み込んで何もしなければ、textarea の値が元の文字列のままであること。
  - メンションの置き換え: コード内では置き換えないこと、壊れた uuid は置き換えないこと。
- E2E（Playwright）
  - 課題を作成し、太字・ネストした箇条書き（Tab）・メンションを入れて保存し、表示に反映されること。
  - コメントの投稿・編集が、見たまま編集のモードと「Markdown で編集」のモードの両方で保存できること。
  - 画像を貼り付けて添付でき、保存後に表示されること。
  - 既存の E2E（添付、メンション、コメント）が通ること。セレクタが textarea 前提のものは、新しいエディタに合わせて直す。

## 11. builder に任せること

- Lexical の拡張の組み合わせと、独自ノードの実装の詳細。
- リンクの URL の入力 UI。
- 表を保つ仕組み（編集できないブロックの実装方法）。
- 外からの貼り付けで、書式を残す・捨てるの判定の実装方法（§4.6 の結果になる範囲で）。
- エディタの読み込み開始のタイミング（§4.2 の条件を守る範囲で）。
- アップロード中のモード切り替えの扱い（§8 の条件を守る範囲で）。
- `MarkdownEditor.svelte` の props の形。ただし、4 か所の呼び出し側から、今の textarea の属性（`name`、remote form の `.as(...)`、`form`、`required`、`id`、`aria-label`、`placeholder`、`rows`）を渡せること。
