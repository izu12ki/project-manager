# Project Manager の課題を API で操作する

課題の一括起票、スケジュール作成、一括修正を、Project Manager の REST API（`/api/v1`）で行う。課題のコメントの取得と投稿もできる。エンドポイントと項目の詳細は同じディレクトリの `reference.md` を読む。

## 事前準備

環境変数を使う。どちらも未設定なら、次を案内して作業を止める。

- `PM_API_URL`: Project Manager の URL（末尾の `/` なし）
- `PM_API_KEY`: API キー（`pm_` で始まる）。各自がアカウント設定の「API キー」カードで発行する（閲覧者は発行できない）。キーは発行した人の権限の範囲で動く。平文は発行直後に一度しか表示されない。

```bash
export PM_API_URL="https://..."
export PM_API_KEY="pm_..."
```

API キーを会話やファイルに書き出さない。curl は常に次の形で呼ぶ。

```bash
curl -sS "$PM_API_URL/api/v1/me" -H "Authorization: Bearer $PM_API_KEY"
```

## 起票（スケジュール作成）の手順

1. **接続を確認する。** `GET /api/v1/me` を呼ぶ。401 なら API キーが無効（失効、または持ち主が無効化・閲覧者に変更された）。ユーザーに伝えて止まる。管理者以外のキーでは、参加しているプロジェクトだけが見える。
2. **プロジェクトを把握する。** どのプロジェクトか分からなければ `GET /api/v1/projects` で選んでもらう。`GET /api/v1/projects/{key}` で、ステータスのキー、課題種別・カテゴリー・マイルストーンの ID、担当可能メンバーの ID を取得する。以降の指定はすべてここで得た値を使い、推測しない。
3. **一覧を見せて確認を取る。** 起票する課題の一覧（タイトル、担当、開始日、期限日）を表にしてユーザーに見せ、承認を得る。承認前に書き込まない。
4. **100 件ずつ分けて起票する。**
   - 1 回の一括リクエストは最大 100 件。それを超えるときはチャンクに分ける。
   - まず全チャンクを `POST /api/v1/projects/{key}/issues/bulk?dryRun=true` で検証する。400 が返ったら `error.fields`（`items.3.dueDate` のように何件目のどの項目かが分かる）を読んで直し、全チャンクが通るまで繰り返す。dryRun は何も書き込まない。値は `true` と正確に書く（`1` などは 400）。
   - 全チャンクが通ったら、`dryRun` を付けずに順に送る。各チャンクは全件成功か全件失敗のどちらか。
   - タイムアウトや通信エラーの後は、やみくもに再送しない。`GET /api/v1/projects/{key}/issues` で作成済みかを確認し、まだ無い分だけを送る。重複起票を防ぐ仕組みはサーバーにない。
   - 途中のチャンクが失敗したら、成功したチャンクと失敗したチャンクをユーザーに報告する。成功済みのチャンクは残る。
   - 親子のある課題（子課題）は、先に親を起票して番号を得てから、子を `parentNumber` 付きで起票する。同じリクエスト内の課題は親に指定できない。子課題は 1 階層まで。
5. **結果を伝える。** 作成した件数と、プロジェクト詳細の `timelineUrl`（タイムライン画面の URL）を伝える。

## 修正の手順

1. 手順 1・2 と同じく、接続とプロジェクトの情報を確認する。
2. `GET /api/v1/projects/{key}/issues` で課題を取得し、絞り込み（`status`、`assigneeId`、`q` など）で対象を特定する。件数が多いときは `limit` と `offset` で全件取る。
3. 変更前後が分かる表（課題キー、項目、現在の値、新しい値）をユーザーに見せ、承認を得る。
4. `PATCH /api/v1/projects/{key}/issues/bulk` で更新する。各要素に `number` と変更する項目だけを入れる。100 件ずつに分け、先に全チャンクを `?dryRun=true` で検証してから書き込む。通信エラーの後は、課題を取得し直して反映済みかを確認する。
5. 最後に更新した件数と `timelineUrl` を伝える。

## 守ること

- 日付は `YYYY-MM-DD`。開始日は期限日以前にする。
- `null` を送ると、その項目を空にする（担当者、親課題、日付、種別、カテゴリー、マイルストーン、完了理由）。項目を送らなければ変更しない。
- 担当者は `assigneeIds`（ID の配列）で複数指定できる。更新では配列全体が置き換わるので、担当者を足すときは現在の `assignees` に加えた配列を送る。
- カテゴリーは `categoryIds`（ID の配列）で複数指定できる。更新では配列全体が置き換わるので、足すときは現在の `categoryIds` に加えた配列を送る。
- 説明（`description`）は Markdown。
- レート制限は API キーごとに 1 分あたり 120 リクエスト。429 が返ったら少し待ってから続ける。
- 課題の削除は API にない。
- 応答にメールアドレスは含まれない。人は `{ id, name }` で表される。
